# YATUI 0.10.2 design

Date: 2026-11-18

## Intent

Ship a reliability and responsiveness update without changing the existing transparent terminal appearance. Preserve the current theme, foreground palette, layout, and background behavior. Do not introduce opaque backgrounds, a new theme, or always-running decorative animation.

## Goals

- Send a real Yandex Rotor `dislike` event for the track currently playing in a radio session, with session ID, batch ID, track ID, duration, and actual played time.
- Avoid sending an additional generic skip/finished event for the same disliked track.
- Move Likes API mutations out of the Bubble Tea update loop and apply UI state only after success.
- Remove the permanent 60 ms volume-fader ticker. Drive volume fading only while a fade is active.
- Do not poll Discord while Discord RPC is disabled; enabling it from settings must start polling immediately.
- Make idle rendering actually coalesce mouse-motion/progress frames while keeping keys and clicks immediate.
- Reduce repeated lyric lookup/style work and track-row style construction where safe.
- Clarify the active dislike state using existing glyphs and foreground styles only.

## Non-goals / anti-goals

- No opaque backgrounds, new theme, glass/gradient effects, or changes to transparent CMD.
- No new UI framework or runtime dependency.
- No GPU compute path. A Go terminal UI is text/layout work; GPU acceleration adds complexity without removing the CPU work that matters.
- No changes to existing configuration defaults or theme selections.

## Approaches considered

1. Narrow hotfix: add the Rotor dislike event and leave rendering/performance issues for later. Lowest risk, but leaves the always-running worker and ineffective idle coalescing in place.
2. Targeted 10.2 reliability/performance update (chosen): fix Rotor event flow, make API actions asynchronous, replace idle polling with event-driven Bubble Tea commands, and optimize repeated rendering work without changing the established look.
3. Visual redesign/theme rewrite: rejected because it conflicts with the transparent terminal requirement and creates unnecessary visual and compatibility risk.

## Implementation decisions

- Use `/rotor/session/{sessionId}/feedback` with event type `dislike`.
- Send the dislike event before advancing the radio queue, then advance without generic skip feedback.
- Keep Like/Unlike collection semantics separate from Rotor dislike semantics.
- Use Bubble Tea messages/commands for UI-owned state transitions. Do not mutate the model from an API goroutine.
- Retain current foreground colors, glyph vocabulary, and layout. Only make the disliked state clearer when active.
- Keep optional RGB behavior as-is; add no default animation.

## Acceptance

- Regression tests cover Rotor dislike payloads, exact-one feedback behavior, asynchronous Like/Unlike result handling, timer start/stop behavior, and idle frame throttling.
- `go test ./... -count=1`, `go vet ./...`, normal build, and nomedia build pass.
- v0.10.2 is based on the reviewed worktree branch and is published only after local verification.
